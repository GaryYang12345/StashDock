# StashDock development rules

## Rule 1: Consistency

Consistency within each application and across the standalone desktop app, Codex MCP App and browser extension is the highest-priority UI/product rule. A change is incomplete until all affected active surfaces have been audited and verified, with host capability differences explicit.

- Use the same shared components for the same job. Do not fork menus, file identities, import forms, confirmation actions, spacing or interactive states between hosts.
- Delete reference and remove tag must share the same destructive action component and normal, hover, pressed, loading, disabled and theme treatments.
- Review the whole interaction: pointer/keyboard behavior, focus return, hover persistence, long content, narrow widths, loading and error states.
- Collection and tag navigation is atomic and idempotent. Selecting a tag clears the prior collection scope; selecting a collection clears the tag. Reselecting the current destination never toggles back to a hidden previous filter. Verify repeated mixed navigation with differently typed references under the same tag in both hosts.
- Shared behavior changes require regressions for both hosts. Explain genuine host capability limitations; never silently omit a feature.
- Shared card presentation has one owner (`ReferenceCardView`), not two copies of matching markup. Host adapters supply platform-specific actions and state; changes to icons, accessibility labels, spacing or hover belong to the shared view.
- Tag filters and action menus share the same Arc hover highlight, with instant keyboard movement and reduced-motion support. Async favicon enrichment must reset failed image candidates; bookmark imports use the same native snapshot/raster pipeline in both hosts and pass inline images to sandboxed UI.
- Add to chat preserves the original single-button interaction: black Add to chat, temporary green Added feedback, then black Add to chat again. Single and bulk Add share this behavior. Only in-flight operations block concurrent presses; intentional repeat additions are allowed. Never introduce a grey persistent Added state, a re-add button, or a reset menu without the user's request. Do not infer current host draft state from past success when no draft-state notification exists.

## Arc UI

- Use the Arc skill for UI work. Inspect the official component/block and reuse it before creating a custom pattern. Keep Arc internals intact; compose documented props and semantic tokens.
- Reference type icons use curated colorful filled assets from established open-source icon sets, bundled locally with their notices. Do not hand-draw SVG paths or substitute letter badges. Keep action/control icons on the existing Arc/Lucide system.
- App launch icons are distinct from transparent inline/toolbar/tray brand marks. Compose the unchanged brand geometry on the platform's appropriate background; keep Apple 1024px source layers unmasked and free of baked lighting. Native Liquid Glass is complete only after actual Icon Composer/toolchain integration and Mac verification, not from a static PNG or ICNS.
- Windows launch artwork fills its square canvas except the transparent rounded corners. Do not add an outside transparent gutter that makes the whole tile smaller in the taskbar. Optical size adjustments scale the approved plate and mark together, preserving their internal ratio; keep Apple source layers separate.
- StashDock's Arc variant uses equal width/height and a 50% radius for icon-only buttons, including their hover and pressed fills, across every host. Labelled buttons keep Arc's rounded shape; help icons keep their established foreground-only hover. Do not shrink one axis independently into an oval. Preserve keyboard focus, loading, disabled and touch behavior.
- AI setup and usage guides share: "Browse your library and use references as context in conversations." Keep one shared copy constant and its translation rather than paraphrasing it per state.
- Default covers and source glyphs share the same curated type identity. Distinguish note, plain text, Markdown, image and Office formats by recognizable assets and complementary semantic cover tints. Maintain an isolated visual specimen for every category; never seed demonstration files into the user's library.
- User-facing text follows the selected interface language (system, English or Simplified Chinese). Keep translations in the shared locale catalog, never translate saved user content, and leave hosts without language settings on their existing default until explicitly enabled. Remove redundant copy; retain necessary instructions, meaningful error recovery and accessibility labels.
- Product copy is concise, specific and professional. Explain a feature's purpose and user value; remove redundancy, not useful meaning. Omit defensive reassurances and implementation explanations. Put optional explanations in the shared black hover/focus tooltip on a small, labelled question-mark icon beside the relevant field or section heading. Use the normal pointer, not the system help cursor. Only its foreground changes on hover, with no background or lift. Never hide essential consequences or recovery actions there. Confirmed integrations show Detected immediately to the left of View guide, vertically centred with the button, not beneath the brand name; peer brand rows keep matching alignment and height. The guide explains actual use, not installation. Undetected integrations offer Set up. Use consistent product names: StashDock Desktop and ChatGPT in Settings; keep internal compatibility identifiers unchanged unless a migration is required.
- File selection is not confirmation. Selecting or reading a file must not write a reference, close the import panel or imply upload success. Save is a separate action after editing title/content/tags.
- Card editing is available through its three-dot menu only, not right-click. Tag right-click actions remain supported.
- Default import forms fit normal desktop panel dimensions without scrolling to find Save. Narrow/short surfaces may scroll but actions must remain reachable.
- Import dialogs size to their actual content, without unused fixed-height space. Coordinate measured outer height and panel changes on Arc's interruptible, non-overshooting smooth spring. Do not animate text scaling or combine competing height animations. Clamp to the available host, keep Save reachable, and test intermediate frames, rapid reversals and reduced motion.
- Establish the first dialog height without animation, preserving fractional CSS pixels. Animate only actual subsequent content changes; unchanged measurements must not restart a spring. Keep transient import visibility below the shelf so opening does not rerender the collection. Check production-mode first response and late layout/paint work, not only animation duration or development-fixture timings.
- Responsive first paint and smooth motion are separate acceptance criteria. Import opens as one coordinated card-and-content fade and upward movement with a soft, non-overshooting landing; close is shorter and lighter. Do not substitute almost-instant travel or timing metrics for the requested visual gesture. Review normal-speed movement as well as intermediate geometry, interruption and reduced motion.
- Dialog headers use Arc's shared 24px gutter (16px on narrow surfaces); title and fields share a left edge, and Close centers on the first title line. Do not add per-dialog header spacing exceptions.
- Batch-import progress uses the approved C2 composition in both hosts: 360px width, panel radius (26px), 32px gutters (24px up to 600px), a 96px illustration region with the text/image/link paper fan at fixed 85% strength, then the centred 18px/500 importing label and the Arc bar with a subordinate 14px percentage to its right. Use 24px between illustration, label and progress. Document cards have no brand logos. Keep one shared implementation and one dimmed modal, with no design selectors in production. Values follow actual completed work; count motion uses the shared smooth spring and reduced-motion jump, never a simulated timer. A55 is an external design reference, not an alternate production component. Judge final optical balance at actual scale in both themes rather than accepting token equality alone.
- Keep discrete tag choices fully opaque. Do not apply navigation-style edge masks to interactive tag chips. Sidebar navigation fading may remain.
- Only one card action menu may be open per surface. Opening another closes the old one without stealing focus; selecting an action and outside/Escape dismissal must clean up hover and focus state.
- File, link and note imports share an explicit Save action, including the initial disabled state. The entire Choose files target opens the picker; do not duplicate it with a trailing Browse label. Files are added only by clicking Choose files (the system dialog; the browser-only preview uses the page chooser), up to 30 MB each so they stay reasonable to hand to an AI conversation; the target does not accept drag-and-drop.
- The desktop shell groups its grey navigation/chrome around a white rounded content surface with a subtle neutral shadow, not area-dividing shell lines. Window controls require visibly distinct hover and pressed fills in both themes. Self-explanatory labelled copy actions need no tooltip.
- Only the collapsed folder is always-on-top. Dashboard panels use normal window Z-order; restore from tray preserves the current mode's policy. Failed mode transitions restore the previous policy.
- Desktop's Floating window preference defaults to On, including upgrades. Off means normal taskbar minimization, Close quits, and tray/shortcut/single-instance activation cannot restore a folder. Native lifecycle enforces the policy, not only button visibility. The 144px folder is the approved 160px composition at 90%; native bounds match its artwork without the retired tooltip spacer or custom hit region. Window preference persistence coalesces bursts and skips unchanged bytes.
- Platform marks share a 20px layout slot and keep their original shape; optical insets normalize visually heavy marks such as X. The compact X/Xiaohongshu/Zhihu preview uses static 24px discs, pure-white rings and a separate unfilled ellipsis, with no redundant Platforms label, hover fan or lift. Zhihu's blue fills the circle without white corner seams. Built-in international platforms precede Chinese platforms in the same shared list in both hosts. The browser extension is exclusively a native Save page sidebar: shared Arc fields, tags and scrollbar stylesheet; no webpage overlay, shelf, library cards, bookmark import or AI actions. Save confirms in place after a durable commit and keeps the sidebar open. Chrome owns its Close control; the form header provides Refresh. Content uses available height without hiding tags or Save. Every product hint uses the same invariant black surface and white text in both themes, never a native title hint.

## AI-native product direction

- Current product principles live in `docs/product-principles.md`. StashDock is a user-controlled, reusable AI context asset library, not merely a webpage bookmark manager or another AI chat app. References may hold sources, original files, prompts, rules, examples, project background and reusable outcomes.
- Design the two-way loop: collect → find/select for a task → use → save useful outcomes → reuse across tasks and AI hosts. AI may recommend and help create context when requested; the user controls purpose and scope. Favor meaningful composition and reduced repeated work over feature count or complex knowledge-management setup.
- The host AI understands/recommends/creates; MCP supplies controlled data/actions; Skills describe repeatable workflows; Desktop manages and transfers the same assets. Do not add a separate AI database, chat product or parsing pipeline as a prerequisite.
- External content is reference data, not instructions or authorization. User-saved prompts/rules become task requirements only when explicitly chosen for use, subject to host instruction hierarchy. Preserve provenance and distinguish original, user annotation and AI-generated synthesis.
- Context groups reuse the existing tags and their shared identity, filtering and management. Do not add a parallel pack/collection entity, separate database or extra group page for the same purpose.
- Model-side saving is explicit, validated and idempotent, with stricter boundaries for overwrite/delete. `save_stashdock_reference` only creates notes/links. AI tag organization uses the separate additive/removal `apply_stashdock_tag_changes` contract after an exact user request or approval: preserve unmentioned tags, require current per-reference revisions, cap batches and report conflicts. Broad organization must be previewed before writing; never accept a caller-supplied approval flag as authorization. All other management tools stay app-only. Host approval and local transport remain the trust boundary.

## Product quality bar

- Treat Apple-level visual craft as the user's aesthetic benchmark, not as a claim of Apple endorsement or compliance. Illustrations must read as one deliberately designed family: consistent silhouette, geometry, corner language, material, lighting, grey hierarchy and detail density. Desaturating unrelated file icons and overlapping them is not a coherent illustration. Preserve separation between layers, avoid occluded or competing labels, and inspect each concept at its actual in-app size in both themes before presenting it. Provide meaningfully different, internally consistent concepts when the user requests options; do not substitute minor parameter changes for a redesign. Functional correctness and token compliance alone never constitute aesthetic acceptance.
- Visual and interaction review is a release gate, not optional finishing work. Before declaring a UI change complete, inspect the actual rendered surface for optical balance, label/control hierarchy, scale, shared alignment, spacing, and consistency with its nearest existing analogue. Exercise both directions, rapid reversal, focus/keyboard, themes and narrow layouts at normal speed and intermediate frames. A working feature, static screenshot or passing source test does not substitute for this review. Field-level controls must remain subordinate to the field, and shared selection highlights must travel continuously in both directions without remounting or jumping. Record observations and fix failures before delivery; never leave obvious polish issues for the user to discover.
- Necessity before novelty. Add only controls, states and mechanisms that solve a concrete user need or correctness requirement. Each visible state must convey a reliable fact and materially change the user's next action; keep transport/history details internal. Prefer established, appropriate product patterns and platform APIs, distinguishing common practice from a formal standard. Do not present personal preferences as industry standards or copy another product's complexity without a StashDock-specific need.
- Installation presence and current connectivity are different facts. A missing/expired handshake, unavailable service or cached package path is not proof of installation or removal. Do not add historical connection badges, diagnostic state taxonomies or configuration switches to compensate for unreliable detection. Show only the minimum actionable information that the implementation can actually establish; never tell users to reinstall based on a connection failure alone.
- Re-entering Settings and returning focus must re-read integration evidence without a persistent result cache. ChatGPT detection requires both the known StashDock package and the host's explicit enabled plugin configuration, including its MCP override. A cache file left after uninstall is not Detected. Parse host TOML with an established parser, never regular expressions, and inspect only StashDock's keys.
- Browser detection retains the extension ID from its authenticated origin and checks only that extension's installation/enablement metadata. A historical handshake alone is not Detected. Prefer Secure Preferences over legacy Preferences so stale fallback entries cannot resurrect a removed/disabled extension. Never inspect or expose cookies, credentials, history or page content for this check.
- Engineering robustness belongs below the UI: one owner per lifecycle, established IPC, bounded recovery and explicit failure handling. Reuse a suitable working mechanism before adding another service, permission, protocol or fallback. Justify added complexity with a demonstrated failure or platform requirement, and verify startup order, restart/recovery and packaging rather than exposing those details as user chores.
- Integration guides place a brand-marked Open app action at bottom right. Prefer a registered client and otherwise its configured official website. Accept only fixed integration IDs, never arbitrary commands or executable paths from the UI; native Desktop launch must retain shell-owned lifetime. Setup guides may offer GitHub Copy when no marketplace link exists. Missing URLs remain visibly unavailable and must never produce fake Copied feedback. Planned Claude setup is an explicitly labelled preview, not a claim of working integration.

- One product, one per-user local library, independent entry points. Desktop and AI plugins must resolve the same authoritative library anchor; overrides seed first setup only, moves affect every entry point, and missing registered data fails closed. Never silently create a second collection or ask users to reconcile divergent libraries. Browser capture uses a local provider, never direct SQLite access; pending browser drafts are not another authoritative library and must not be presented as successfully saved references.
- Settings describe complementary tasks, not deployment internals. Desktop separates Browser extensions (Chrome, Edge, Firefox, Safari) from AI plugins (Codex, Claude). An AI-hosted panel shows Browser extensions and Desktop app, never competing AI brands. Planned platforms keep complete brand-row presentation with an explicit Coming soon state. Detection must distinguish a confirmed StashDock registration from guesses about installed browsers, cached host packages or running processes. Installation guidance uses configured real destinations; never invent store links.

- Settings are deliberately small and understandable. Prefer clear defaults and a few useful choices over engineering switches. Do not add backup/restore, storage breakdowns, telemetry or diagnostic panels without a new user request. Desktop and the ChatGPT plugin share storage information, Open folder and Change location, using one storage component and the same verified relocation engine. Appearance preferences are independent; automatic theme follows the host. Only genuinely host-specific functions (desktop startup, global shortcuts and desktop update checks) differ. Plugin updates are managed by the host. Never invent an update check or a disabled duplicate desktop control. Desktop Check for updates opens one compact status dialog (grey brand mark, spinner while asking GitHub, then the version; a GitHub button only when a newer release exists). About rows show the version as a grey `vX.Y.Z` beside the product name.

StashDock is intended to be a commercially credible, influential product. Professional polish and consistency are acceptance criteria, not optional finishing work. Audit the complete user journey and every intermediate state; never call a change complete based on static screenshots or passing source-pattern tests alone. Regressions, redundant controls, unintended blank space, competing overlays, missing feedback, clipping and inconsistent actions must be resolved before delivery. Match deliberate UX intent instead of applying rigid layout shortcuts. Record evidence and be honest about any check that could not be performed.

## Stage review and optimization (manual trigger only)

The user explicitly triggers this workflow by requesting “阶段性检查和优化” or equivalent. Do not schedule it, run it periodically or start a broad refactor during ordinary feature/bug work without that request.

1. Save a recoverable source/build snapshot and consistent library backup; establish current entry points and data/behavior invariants.
2. Map ownership across desktop, Codex MCP App and the Save page extension. Consolidate genuinely shared domain logic; keep host-specific capabilities in adapters. Improve naming and responsibility boundaries without redesigning approved UI or introducing a new architecture unnecessarily.
3. Remove only demonstrably retired, unreferenced implementations and tools. Verify imports, build scripts, fixtures and packaging first. Preserve user data, session/profile directories, licensing notices and recovery snapshots; uncertainty is not permission to delete.
4. Audit consistency, correctness and performance: error/success feedback, validation, URL/tag identity, async stale completions, cancellation, listener/timer cleanup, concurrency limits, retryable cache failures, repeated window transitions and unnecessary work/bundle dependencies.
5. Fix confirmed issues with focused regressions. Run type checks, active frontend/native tests and packaging/asset parity checks; verify affected actual surfaces, including repeated operations and failures, with isolated fixtures for mutations.
6. Update the current architecture and release instructions, distinguish historical evidence from active acceptance, and report what changed, what was verified and remaining risks. Never claim a complete absence of bugs from a passing suite or a single interaction.

## Data and verification

- Pages are read the way a browser shows them: in both hosts a pasted link is rendered once in the isolated system renderer for its title, text and cover (a few seconds are acceptable), with a bounded direct document read alongside as a fallback; rendered text is preferred. Batch imports do not read pages in the foreground (link context is a supplement the receiving AI can extend from the URL). Background screenshots have one leased owner and two isolated lanes, within the existing two-renderer cross-process admission limit. Each image job permits at most two attempts: a failed first screenshot shows the normal default cover at once, and one background retry, scheduled after every new cover and without a loading state, replaces it only if it succeeds; otherwise the default cover stays. Quitting an entry point hands its in-flight jobs back without spending an attempt and frees the lease for the next owner; only an expired deadline (a crash) counts as a failed attempt. Do not add a cooldown or use an OG image to hide screenshot failure. Job deadlines are independent of renewable provider leases; validate attempt tokens/deadlines on publication and recover expired work without reviving exhausted tasks. Helper deadlines include queued and retiring-child waits. Desktop receives external provider changes through one coalesced SQLite data-version/expiry observer on the existing worker connection, never repeated whole-library polling in React.
- Optimize for a measured balance of performance, accuracy, efficiency and implementation complexity. Prefer bounded concurrency, reuse and removing unnecessary work; do not trade reliable results, isolation or ordinary-device resource budgets for nominal throughput. Retain a simple existing implementation when added complexity has no verified user-visible benefit.
- Link context is a fast, bounded introduction for the receiving AI, not exhaustive document ingestion. PDF links remain title/URL-only in foreground imports: do not download full binaries or extract their text. Optional background PDF covers render only page one, within a 5 MiB download cap. HTTP document reads may use gzip/Brotli with limits on decoded bytes; connection reuse must remain bounded and keyed to checked endpoints, with redirects and private-network protection unchanged. Slow screenshot pages retain the actual task deadline rather than an earlier blank-viewport cut-off; never relax blank-image checks to improve nominal success rates.
- Preserve unrelated user changes and collection data. Use isolated fixtures for mutations and consistent SQLite backups before deployment.
- Store original file bytes unchanged. Title, context and tags are reference metadata, not modifications to the original file.
- Windows desktop Copy for AI and native dragging share one immutable outgoing file-group export and Shell data object. Web references retain Markdown; every managed file, including Note's `.txt`, also transfers its latest original bytes beside the Markdown context. Outgoing transfer snapshots must never be used by Open, which follows the file reference rule below (original, else backup). Keep files separate, not zipped. Deduplicate originals, disambiguate filenames, retain context and selection order, validate paths and bound total bytes. Never substitute a path or silently fall back to long text on native failure. Materialize clipboard formats so copying survives app exit. Keep the black/green/black button feedback. Browser-only text copy and Codex draft Add remain explicit host adapters, not claims of native file attachment.
- Do not label a path, base64 text, or MCP context resource as a native composer file attachment. Native file attachment requires a documented, available host capability; disclose host limitations and preserve StashDock supplemental context.
- File understanding belongs to the receiving AI, not StashDock. Preserve original bytes and user-added context; do not add PDF/Office/OCR parsing services as a substitute for original-file delivery. Native original-file plus Markdown sidecar transport is separate from MCP text context. A host upload API or resource blob alone is not proof that the file is attached to the active draft.
- Search has one contract in every host (`reference-search.mjs`, `library/search.rs`, `search-index.sql`, fixture `tests/fixtures/search-contract.json`): every whitespace-separated term must occur as a case-insensitive substring; a trigram FTS5 index kept current by SQL triggers serves terms of three or more characters and LIKE serves shorter ones; relevance first, then newest. Never maintain the index by hand in write paths or fork the rules per host.
- Default AI context carries task material, not library bookkeeping. Keep title, URL, meaningful non-duplicate source, available author/publication date, tags and content provenance; omit import browser, bookmark folders, saved date and managed absolute paths. Label saved content, summaries, selected text, Note projections and file annotations honestly. Explicitly report known capture incompleteness and export truncation without altering user-edited final context (including an intentional empty value). Native delivery uses the actual collision-safe attachment names and omits duplicate Note projections only after delivering the original TXT; MCP keeps readable Note context and separate ID-based original-file instructions. JS/native formatting share executable contract fixtures.
- A user-selected file reference requires an original-file reading workflow. MCP draft context identifies the reference ID separately from editable supplemental content; `get_stashdock_file` resolves only that ID's existing managed asset. The receiving AI must read it with permitted host tools and the appropriate skill before making content claims. A path lookup is explicitly not a content read. Missing files, inaccessible execution environments and unsupported formats must be disclosed, never replaced by guesses from metadata.
- The retired browser shelf, HTTP-to-desktop MCP adapter and browser drag broker are not supported fallbacks. Use the documented MCP global/thread entrypoints; keep active Save-page capture, migration/recovery needed to preserve data, native window recovery and capability checks. Release cleanup removes dead implementations and their obsolete tests/scripts, not user data or necessary failure handling.
- Open files by saved reference ID, never by a path supplied by the UI or a model. Validate the library backup boundary and the original's type, and never execute active scripts as a file-opening shortcut. Files chosen for import are identified by short-lived tokens from the system dialog; the page/App never sends a path.
- A file reference points at the user's original file and keeps a managed backup in the library (`originals.rs` / `original-files.mjs`, shared rules and tests). Before Open, native transfer or MCP reads, a changed original (size/modified fingerprint) refreshes the backup and, unless the user wrote it (`contentEdited`), its searchable text. Open shows the original while it exists; a moved, deleted or offline original silently falls back to the backup, and a missing backup is restored from a reachable original. Older backups edited after their original stay authoritative. Dropped files and Notes have no external original; their backup is the file. Note creation saves its entered body as a normal `.txt` asset; its text/search fields are derived from that file. Card context editing is supplemental (`context_override`) for every file type and never overwrites a file. Deleting a reference removes its library backup (never the original or anything outside the assets folder); do not add an internal Note reader or snapshot opening. Backups are stored by absolute path; on library open both hosts repoint a missing backup to the same file under this library's `assets` folder (`asset_paths.rs` / `asset-paths.mjs`), so a library copied to another drive, sync folder or computer keeps working. Changing the stored format to relative paths needs every entry point updated in the same release.
- Run type checks, frontend/native regressions and rendered UI checks before rebuilding and installing both surfaces.
- Desktop release optimization is not production packaging: backend-only releases must enable `tauri/custom-protocol` to embed the frontend. Never distribute a desktop built against `build.devUrl`. Verify the actual installed WebView loads packaged assets and the shelf opens with the development server stopped; process liveness and browser fixtures alone are not launch acceptance.
- Refreshes reconcile unchanged reference objects/arrays. Async paginated work checks invalidation between requests. Preview caches are bounded, deduplicate running work without evicting its concurrency reservation, and reject work after shutdown.
- Keep disk/SQLite/image operations out of synchronous Tauri window commands. Expensive work has an explicit admission bound and owns its slot until actual completion, including cancellation and errors. Do not impose an arbitrary hard memory cap on the UI process; bound payloads, decoded images, helpers and owned renderers instead.
- Passive shelf pagination reads compact metadata and only that page's covers, not every original body/thumbnail. Desktop's shelf list carries no bodies or edited context (`read_shelf`); content editing reads that reference by ID (`get_items` full). Background cover/icon updates name the references they changed, and the shelf re-reads only those, coalesced, instead of reloading the library. Retrieve selected AI context by ID. Original-file resolution/transfers still use current authoritative files. Pause optional image refresh during foreground reads and dialogs. Search and browsing are stable: each query or collection change replaces the shown cards once, never in batches. Desktop keeps the last settled results until the index has answered the typed query (an empty query is answered at once), then swaps them in a deferred, interruptible render; the field and navigation never wait. Desktop's shelf is virtualized by rows (`VirtualShelf`, TanStack Virtual) so a change mounts only the cards near the viewport whatever the library size; results start at the top after a query or collection change. Navigation and tag menus are memoized with stable handlers. The field swaps its glass for a spinner only when results lag the typed query by more than 300 ms, in both hosts.
- Background leases are coordination, not activity logs: renew near expiry, keep unchanged reads free of writer locks, and use database change detection to avoid repeated full empty-queue scans. Document the active cadence and per-process resource budgets. Preserve bounded, visibility-aware browser recovery; never reduce reliability merely to remove a timer. Performance acceptance uses isolated before/after measurements plus actual interactions, not bundle size or guessed speedups.
- Background enrichment renders each page once for its cover and the text read from that same render (`Rendered`, `merge_text` / `publishRenderedText`). Rendered text fills a reference imported without text, or replaces a shorter direct read from the background text lane, and then settles it; it never touches user-edited text, edited context or a settled import. It is not exhaustive ingestion. Process missing covers before icon-only maintenance, reuse supplied raster icons, publish screenshots before optional icon fetches, and attempt rendering only once per queue attempt. Keep background concurrency bounded rather than increasing load to hide latency. Live loading skeletons pulse until completion/failure, with reduced motion respected; no arbitrary animation expiry while real work remains.
- Browser-bookmark imports save the selected links at once in bounded chunks with one shared Arc progress indicator that follows the actual saves (it stays up at least 900 ms so the import is felt); text and covers then arrive from the background render. Batch import replaces the form with a compact, centred progress surface over the shared dimmed backdrop, never an indicator below the bookmark list or a second stacked modal. Show only neutral importing progress, not body-extraction instructions, success summaries or missing-content counts. A pasted link's lookup result is settled at save, including an unavailable body. The screenshot job reads text from its render; only when the render produced no text does it read the page directly, after publishing the cover. Short rendered text is kept as it is. The leased text lane only fills references that already have a cover (for example older ones or browser saves), with guarded ID/URL/empty body/final-context checks and atomic FTS publication. Never overwrite user metadata or imply inaccessible pages were read completely. Warm public renderers stay isolated from user browsers, clear site state before reuse, pause idle scripts and retain bounded admission/idle cleanup.

## Browser capture and platform sources

- Chrome, Edge and Firefox extensions have one shared Save-page form, extractor, session lifecycle, RPC and outbox. Keep only native sidebar APIs and generated manifests browser-specific. Chromium uses a service worker; Firefox uses a module event page. Preserve document-ID guards and optional user-approved website access; never emulate access by scraping another profile. Firefox's stable runtime ID is distinct from its per-profile origin UUID. Installation detection reads current matching extension metadata, not handshake age. Generate browser packages from canonical sources with dependency notices; do not hand-maintain copied bundles or change signing/security settings for testing.

- Save-page transport reads only the current canonical URL's bounded duplicate summary and the tag names, never the whole library or its thumbnails. Saving returns a compact transaction receipt. Duplicates require explicit Replace/Keep confirmation; cancellation writes nothing. Replacement preserves card identity, creation time, favorites and separately edited AI context, and rechecks the confirmed revision inside the write transaction. Retry the same operation only after an explicit user action; a bounded shared receipt prevents repeated replacement after an uncertain response. Remove the retired browser shelf cache while preserving unfinished legacy operations; do not revive shelf APIs as a fallback.
- Browser-origin authentication cannot assume privileged extension GET/HEAD requests carry Origin. Protected capture lookup and tag reads use bounded JSON POST RPCs; keep registration/Origin checks and never substitute caller-asserted origins. Preserve concrete provider errors rather than misreporting every rejection as a missing app. Text enrichment has its own single-owner lease, independent of image-only providers, and immediate URL saves must remain eligible for deferred metadata completion without overwriting user edits.

- The Save page extension has no Settings screen, settings entry or automatic setup tab. Keep configuration in Desktop/AI-hosted Settings. Missing-provider guidance stays inline in the Save form with a bounded connectivity recheck; connectivity polling must not repeat installation registration or integration scans. Browser icon-only controls import the same circular control policy as Desktop and MCP.

- Platform-wide saved-collection import and independent sign-in connectors are retired. Existing ordinary browser bookmark import remains in desktop/Codex. Platform entries open built-in or explicitly user-saved, validated HTTP/HTTPS destinations in the normal OS-default browser; StashDock never supplies another profile or manages that browser's lifetime. Custom destinations persist in the shared SQLite preferences, not separate per-host browser storage. WeChat is not a supported platform.
- Clicking the extension toolbar opens its native Save sidebar and requests optional website access once through Chrome's own consent dialog. After consent, the open sidebar automatically reads its window's current HTTP/HTTPS page on tab switches/navigation; closing it stops reads. Never read inactive/background pages, browser/extension/file URLs or our form. Retry always reads the current page, not the previous capture. Authorize worker requests by extension page, window, tab/document identity and capture token. Latest tasks supersede old tasks without stale completions overwriting a new draft. Ephemeral capture sessions survive worker suspension, not browser restart; only Save writes a reference. Required host permissions remain localhost-only; broad website/screenshot access is optional, never silently granted by automation. No Cookie access, password storage, session export, authenticated API replay, challenge bypass, browser debugging requirement or platform account writes.
- Native desktop window boundaries must match the visible UI. The opaque, resizable dashboard uses Tauri's platform frame/shadow; the small transparent folder is a separate topmost, taskbar-free window. Never recreate a permanent oversized transparent dashboard canvas or paint a separate dashboard shadow HWND. Native geometry, monitor/DPI placement, readiness, visibility and rollback have one lifecycle authority; frontend components request forms, not per-frame position/region writes. Preserve selection/query/scroll on handoff; do not remount the shelf. Validate actual packaged native windows, not browser-only mocks.
