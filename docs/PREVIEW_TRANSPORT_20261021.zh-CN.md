# 正文与截图链路的针对性优化

## 产品边界

链接 context 用于让 AI 快速了解参考资料，不追求完整读取所有文档。PDF URL 的前台读取只返回文件名/标题与链接，不获取全文，不启动渲染器；无扩展名的 PDF 通过响应类型或短前缀识别后停止正文下载。保存链接仍有效，原始 URL 供接收方 AI 使用。

后台 PDF 封面只渲染第一页，移除逐页文字和文档元数据提取；下载上限由 32 MiB 收紧到 5 MiB。大 PDF 使用正常默认封面。

## 工程变更

- HTTP Client 按域名和已验证的精确端点复用，每进程缓存最多 4 个、空闲连接 30 秒、每端点最多 2 个空闲连接。请求仍有独立超时；每次重定向仍重新验证公共 DNS，禁止系统代理和私网目标，TLS 验证不变。
- HTML 支持 gzip/Brotli 流式解码，大小限制作用于解码后的数据。图像下载保留原有 identity 请求；不安装额外浏览器、不启用 Cookie。使用项目已有锁定版本的 flate2/Brotli 库，显式关闭可能由依赖统一启用的 reqwest 自动解压，避免双重解码。
- MCP 使用 4 个按需启动、空闲退出的正文 helper 会话，复用进程及 HTTP 连接。截图仍为独立 2 会话，总渲染额度保持 2；取消、总超时和私有目录清理沿用原会话机制。
- 普通 HTTP 和截图代理共用已验证端点的成功地址排序，不把未验证地址加入缓存。
- 去掉截图中独立的 10 秒空画面提前失败点。正常画面稳定后仍立即截图，慢页面最多使用原有 22 秒任务预算；不延长重试次数、不添加重试间隔、不抓空白图。
- 画面探测不再把 `readyState=loading` 等同于空白。第三方脚本可能阻塞文档完成，但正文已绘制；此时维持 `ready=false`，同时保留真实 `drawable` 与布局签名，让既有有界回退捕获已显示的页面。真实空白仍然失败。
- Windows 获取位图使用 WebView2 的 `CapturePreview` 原生视口接口，沿用既有协议和图像后处理上限，不再把该命令发送给 DevTools 合成器。不在截图前强行停止加载；该实验会截断部分动态页面，已移除。被导航取消的单个资源 continuation 回调不再使整个 WebView 会话失败；真实主文档失败、会话错误、命令错误和总超时仍有效。

## 验证与限制

- 一致性备份：`artifacts/preview-transport-20261021`，含修改前桌面端、helper、相关源码及 SQLite 一致性快照。
- Native 测试覆盖 HTTP 连接复用、压缩正文、解压后限额、损坏流、缓存上限/到期、私网拒绝、PDF 跳过与无网络的 `.pdf` 快速路径。
- 会话测试覆盖四路读取、排队复用、关闭和取消。截图任务仍覆盖恰好两次尝试、无间隔、任务到期与迟到结果保护。
- 公开网址对比脚本仅接收明确提供的 URL，不读取或修改用户收藏。CUHK Mathematics 与 WCSU 在修改前后的结果受 DNS、网络与站点加载波动影响；不能由一次成功推导任意网站稳定成功，也不把去掉 OG 兜底前的封面一概称为截图。
- 早先文档中的完整 PDF 正文提取/32 MiB 预算为历史实现，本文件记录当前边界。
