# AI native 下一阶段：能力盘点与建议

2026-10-16 初始设计讨论，以下保留当时能力盘点与建议。后续用户确认组合复用已有 tag，不新增集合结构；首轮实现情况见 [AI context 实现](ai-context-20261016.md)。原则见 [产品设计原则](../product-principles.md)。

## 当前实现的真实能力

核对来源：`plugins/stashdock/server/create-server.mjs`、`library.mjs`、`plugins/stashdock/skills/use-stashdock/SKILL.md`。

- 模型可以调用 search_stashdock，按 query/tag/favoriteOnly 查询，取得小批量摘要；get_stashdock_item 按 ID 读取保存的正文和拼装 context；open_stashdock 打开可视面板。旧 get_stashdock_dock_url 只是兼容入口。
- 搜索是文本子串匹配加时间排序，不是向量检索或任务相关性排序。单次最多 50 条，模型搜索入口没有翻页参数。可以多关键词分次检索，再由宿主模型判断相关性；不能声称检索已穷尽整库。
- 现有 Skill 指导搜索、确认歧义、按需取正文、保留来源和处理不可信资料。没有“推荐工作流”的专门输出规范，也没有保存工作流。
- 导入、编辑、标签、删除和附件准备等能力是 app-only；它们存在不代表模型能直接调用。当前对话里让 GPT 保存新 reference 仍需新增受控能力。
- 保存内容可能有用户编辑的最终 context；推荐应区分原始正文与用户补充。二进制文件路径/metadata 不是文件理解；宿主须具备读取/上传能力。
- 自然语言推荐可以现在使用现有工具完成，但自动把推荐卡片选中/高亮、写回或作为宿主原生文件附件，不是现有模型工具已经提供的功能。

## 最值得做的工作流

### A. 找到当前任务真正能用的收藏（第一优先）

例：“帮我看看已有收藏里哪些适合这个项目，只挑最有用的几条。”

基于宿主已获授权的任务/项目背景，分主题检索 → 读取候选 → 输出 3 到 5 个强候选，逐条说明用途、依据和缺口。没有合适项就不凑数。

先用现有工具和工作流规范验证效果；再根据体验决定是否增加推荐卡片、跳转/定位、批量读取和分页。不先建向量库或独立推荐模型。

### B. 在 AI 使用中存回可复用资产（第一优先）

例：“把刚才这套 review prompt 存下来。”“把这几个来源存到 StashDock，并保留我为什么要用它们。”

新增小范围、模型可见的保存工具，先支持文本/笔记和已知链接；沿用共同校验、去重、事务和来源结构。用户明确指定内容时直接新增；AI 提炼或范围不清时预览再保存。

保存有核验结果，不假装收藏成功。更新/删除继续保留现有边界，不为新增需求开放通用 SQL、任意路径读取或全部 CRUD。

### C. 可复用的 context 组合（下一步建议）

例：“论文润色”组合包括写作要求、自己的好范例和术语表；“前端实现”组合包括设计规范、参考页面和检查清单。

用户后续明确：组合就是现有 tag 下的 references。沿用已有标签的命名、筛选和增删，一条 reference 可有多个 tag；不新增 pack/集合实体、数据库或管理页。本次使用的交付快照仍独立于之后的编辑。

Desktop 和 AI 面板用同一数据模型，原始文件与补充 context 的交付仍走已验证的宿主路径。

### D. 对话成果变成下一次的起点（下一步建议）

例：“把今天确定的需求、决定和下一步整理成一张 ref，明天换个对话也能接着做。”

生成简短、自包含的交接 context：目标、已确定决定、约束、当前状态、下一步和必要来源。不是完整聊天记录或模型内部推理，也不是无限后台记忆。

用户可在另一项目、另一对话或另一 AI 中复用。依赖当前宿主实际可见的内容，不承诺抓取全部历史聊天。

### E. 从一次成功中沉淀方法（可与 B/D 共用）

例：“刚才这个排查方法很有效，整理成以后能重复用的清单。”

保存复现条件、操作步骤、验证标准、失败/不适用情况和示例，提炼可迁移部分而不是照搬本次对话。可以先是普通 context reference；有明确重复工作流后，再考虑导出为 Skill。普通 prompt 不强制套 Skill 结构，生成的 Skill 不自动安装或执行。

### F. 对现有 context 做体检（后续）

例：“这些规范是不是有矛盾，哪些可能已经过时？”

对用户选择的一组资料指出冲突、重复和缺失，附原文依据。先是一次性的只读检查；不默认后台扫库，不自动覆盖或清理用户收藏，也不新增复杂健康度面板。

## Desktop 的对应价值

保持一个可视、便携的 context 资产管理面，不另起聊天产品。优先让 prompt/规则/范例容易辨认和编辑、组合整体交付、AI 存回的成果即时可见，并保留原始文件。

后续可提供“让 AI 帮我挑/整理”的明确交接入口，但只有验证过宿主能力才承诺一键联动。不在后台窥探前台应用或自动注入任意 AI。受支持 AI 使用同一 MCP 能力，其他 AI 保留现有原始文件与 Markdown 交付。

## 建议顺序与检验

1. 先打通 A + B：为项目找收藏；把对话中的好 context/链接存回来。
2. 再做 C：把实际反复一起使用的资产变成组合。
3. 用已有保存能力承载 D/E，避免每个场景一个新页面或一个独立工具。
4. 观察实际失败后再决定检索增强、批量读取、版本关系等基础能力。暂不做 RAG 聊天、全自动记忆或大而全的 Skill 市场。

验收应检查：候选是否真正用于任务、无结果是否诚实、来源/批注是否保留、一次明确保存是否完成、重复请求是否产生副本、另一入口是否看见、下一次是否找得到并直接能用。优先用代表性任务和人工验收，不为此默认新增遥测。

## MCP / Skill 的分工及来源

MCP 提供受控数据与动作；Skill 教宿主模型何时、如何组合这些能力。推荐智能来自宿主模型，不来自 MCP 协议本身；Skill 不能凭空增加权限或突破 app-only 边界。
