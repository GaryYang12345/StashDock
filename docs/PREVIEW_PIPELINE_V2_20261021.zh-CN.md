# 截图队列与导入并发重整

## 当前约束

- 两端 URL 导入正文处理从 2 路改为 4 路，Native 阻塞工作额度同步调整。普通 HTML 仍使用既有公开网络提取器；不额外等待截图，不读取浏览器账户。
- 后台图片保留单租约所有者，内部使用两条任务通道。Desktop 使用两个隔离、可复用的 WebView2 槽；MCP 使用两个有界串行 helper 会话。跨进程渲染总额度仍是 2，没有关闭沙箱、扩大传输上限或捆绑浏览器。
- 每张图片最多尝试 2 次。首次失败立即排到补试优先级，没有冷却期；第二次失败终止，使用应用默认封面。已保存的封面、用户自选封面和其他收藏元数据不被覆盖。
- 普通截图失败不再追加 OG 图片下载来掩盖失败，也不在补试前获取可选元数据。已成功截图仍立即发布；仅缺 favicon 的维护任务优先级低于缺封面的任务。

## 超时与恢复

- 核心页面渲染预算 22 秒，DNS 等外围工作另有界限；Native single-flight 等待预算为 30 秒。MCP helper 的 55 秒预算从入队开始，包括等待旧进程退出/私有目录清理的时间，而非到真正执行才计时。
- 单条队列任务的恢复截止时间为 60 秒，与服务可续期的 90 秒租约分开。过期任务按剩余额度恢复；耗尽额度后标记失败。服务在线不能让过期任务继续显示 working。
- 发布和结束检查 ID、URL、attempt 次数和任务截止时间；MCP 还校验当前租约所有者。旧尝试不能覆盖已领取的新尝试，已删除/换 URL/自选封面的记录不会被复活或覆盖。
- Desktop 在现有后台数据库连接上用一个合并后的 `data_version` / 任务到期观察器接收其他宿主的变更；仅变化时发出既有事件。没有新增 React 全库轮询、磁盘文件遍历或界面计时器。MCP 沿用可见、无前台操作时的有界页面刷新。
- 旧版遗留未结算正文的后台补全通道保持原有策略；本次“立即再试一次后默认封面”针对截图任务，不将正文为空误报为截图失败。

## 验证入口

- `tests/preview-worker.test.mjs`：双通道不同任务、上限 2、立即一次补试、耗尽后不复活、独立任务到期与迟到结果保护。
- `tests/preview-session.test.mjs`：旧 helper 退休/清理阻塞时，排队任务仍受总超时约束，不额外创建进程。
- `tests/preview-selection.test.mjs`：服务存活但任务过期时不再显示 working。
- Native `web_preview` 测试覆盖 CAS 领取、立即补试、过期恢复、结果保护和只读跨连接变化检测。
- `scripts/benchmark-preview-lanes.mjs`：三个公开示例站点，旧串行与新双路的小样本对比，不读取用户 URL，不作为任意网站或全机 CPU 的保证。
- `scripts/verify-preview-lanes.mjs`：临时独立收藏库，验证两张真实截图和一个不可解析域名在两次失败后结束、正文不变。

正式发布前仍需核验实际运行服务已换到新模块。仅复制插件文件不能替换仍在内存中的旧 MCP 服务；资源 URI 已更新为 v59，避免继续沿用旧面板资源。
